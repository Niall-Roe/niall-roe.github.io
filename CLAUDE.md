# niall-roe.github.io

Published, self-contained interactive editions of pre-1900 papers, plus a few concept
apps. This repository **owns the live files** — the copy here is the one that is
served. If a page needs a change, change it here.

## The site shell

The public site at `niallroe.com` — home, `teaching/`, `cv/`, `illustrations/` and `404.html`
— is generated from `_site/`:

```bash
./_site/build.sh          # writes the shell pages
./_site/build.sh --check  # says whether they are behind _site/
```

Same rule as the papers: never hand-edit the generated `index.html`. Edit `_site/common/`
(head, nav, footer) or `_site/pages/` and rebuild. `CNAME` sets the custom domain and must
stay at the repository root.

## Building a page

Every page is assembled from parts:

```bash
cd <paper> && ./build.sh          # writes index.html from src/
cd <paper> && ./build.sh --check  # says whether index.html is behind src/
```

Never hand-edit a built `index.html` — edit `src/` and rebuild. In
`On-Small-Differences-In-Sensation`, `src/02_article.html` is itself generated by
`tools/`, so do not hand-edit that either.

Pages are single files with nothing fetched at run time: no external scripts, styles,
fonts or data. They must work offline, over `file://`, and inside a sandboxed iframe.

`src/03_lib.js` and `src/04_scaffold.js` are shared verbatim across papers, so anything
written for one page runs in another. Do not fork them per paper.

## Example notes

Each paper keeps its examples in `<paper>/notes/`, **one file per example**, named
`NN-slug.md` where NN is reading position. Each carries `---` frontmatter (`number`,
`status`, `container`, `group`) followed by the entry's sections. The format is
specified in [`_status/CONVENTIONS.md`](_status/CONVENTIONS.md) — read it before
editing one.

Edit the single file for the example you are working on; do not rewrite the directory.
The old monolithic `<Paper Name> - Examples.tex` is kept as a backup of the state
before the split and is no longer read — do not edit it, and do not treat it as
current.

**The approval rule.** When you finish implementing suggestions, do not record them as
completed. Move them to `### Awaiting approval`, set that entry's frontmatter to
`status: awaiting`, and say so in your reply. They move to `### Completed` only after
Niall has looked at the page and confirmed. The notes file must never claim his
sign-off on his behalf.

Rejected work goes back to `### Suggestions` with a note on what was wrong, rather than
being deleted — the next attempt should know what the last one got wrong.

Square brackets in a notes file are Niall's own marks: `[great]`, `[not this]`, or a
quantity the reader should be able to set.

## House style for examples

- Anchor a trigger on the sentence stating the **result**, so the reader has read the
  content before clicking.
- Drive Peirce's own numbers in his own sentences: wrap the figure in `.live`, colour
  it to the control that moves it, and revert to what he printed when the example shuts.
- Sliders over number entry or dropdowns wherever the quantity is ordered.
- Where a paper restates something an earlier paper covered, reuse that example's
  graphic and say so, rather than inventing a second picture of the same thing.
- Let the text do the explaining. No rhetorical flourish, and none of the
  "it's not x, it's y" construction.

## Status dashboard

```bash
python3 _status/build.py --open
```

Regenerates `_status/index.html` from the repository and the notes files. Run it after
a working session. The output is gitignored; `build.py` is not.
